# 文字密度と日本語入力の表示

2026-11-01。端末のフォントを横方向に94%にし、文字サイズ・行高を保ったまま少し詰めた。SwiftUI と独自キーボード・変換パネルの字間は -0.2 pt。端末は実際に変換した UIFont を SwiftTerm に渡すので、表示だけでなく列数・カーソル・選択の計算も同じ文字幅を使う。依存ライブラリの変更はない。

独自キーボードの常設の読み・候補欄を削除した。読みがある間だけ、端末のカーソルの下、空きがなければ上に小さなパネルを重ねる。画面端で位置と幅を制限し、長い読み・候補は横にスクロールする。読みの下線は現在の文節、候補の背景は選択中の候補を示す。文節・候補のタップ、上下キー、変換、確定、取消は既存の実辞書エンジンを使う。高さの少ない横画面では読みと候補を一列に並べ、候補の操作領域44 ptを保つ。

パネルはキーボードの外にあり、表示・非表示で端末の行数やキーの位置を変えない。入力が空、フォーカス喪失、タブの離脱では隠す。カーソル追従の表示更新はパネルが必要な間だけ動かし、弱参照のターゲットを使って表示階層を保持し続けない。アプリの非アクティブ化・回転・言語変更時のリピート停止、確定と改行の分離を維持する。

通常の iOS キーボードの変換表示は引き続き OS が担当する。極端に小さい表示領域ではパネルの高さも領域内に制限する。

独自 UIInputView の size class と UIWindow の座標・画面方向が横画面でも縦画面のままになる環境があったため、実際の入力ビューの幅をウィンドウの短辺と比較してキーボード高を決める。高さの制約と、[Apple の self-sizing 契約](https://developer.apple.com/documentation/uikit/uiinputview/allowsselfsizing)に従った `systemLayoutSizeFitting` の希望高を揃える。横画面はタイトルバーと状態行を省き、接続先・設定を下部の操作メニューから開けるようにして、端末の表示領域を確保する。

## 検証・レビュー

- 純粋な配置テスト3件でカーソル上下、右端、横画面、長い入力、小さい領域を確認。
- iOS の実 UIFont / CoreText と SwiftTerm を使うテストで、文字幅と実際の列数が変わり、文字の高さが変わらないことを確認。長文が省略されず保持されること、空のパネルが非表示になることも確認。
- UI テストで実辞書の「にほんご」→「日本語」、開始前後の端末高さとキー位置の不変、確定後の非表示、変換中の回転、横画面の候補タップを検証。
- 変更範囲を直接レビュー。パネルの参照・表示リンクの寿命、フォーカス・表示階層の切り替え、座標変換、横スクロール、候補確定経路を確認。通信・鍵・クリップボードの権限は変更せず、入力を自動実行する経路は追加していない。
